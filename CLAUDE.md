# CoTab

CoTab is a Flutter mobile app (Android and iOS) for student houses and travel groups: shared expenses, a shared shopping list and a rotating chore schedule in one place. It is a university course project (Mobile Programming, Istanbul University-Cerrahpaşa), so the code must stay simple enough for every team member to read and understand every file.

- Product scope and setup: [README.md](README.md)
- Roadmap, phases and who owns which module: [docs/Road_Map.md](docs/Road_Map.md)

The app is offline-first: data is stored locally in SQLite (sqflite). Firebase (Auth, Firestore) is added later on a separate branch.

## Folder structure

```
lib/
  main.dart                   # App entry point: MaterialApp, theme, localization
  models/                     # Plain data classes (User, Group, Expense, ...)
  screens/                    # One file per screen
  services/                   # Database and, later, Firebase code
    database_helper.dart      # Opens the SQLite database and creates the tables
  widgets/                    # Small reusable widgets shared by screens
  utils/                      # Helper functions (formatting money, dates, ...)
  l10n/
    app_en.arb                # English texts (default language)
    app_tr.arb                # Turkish texts
    app_localizations*.dart   # Generated by Flutter, do not edit by hand
test/                         # Widget and unit tests
docs/                         # Project documents (roadmap, reports)
  CHANGELOG.md                # Log of every change, newest first
```

## Commands

```bash
flutter pub get      # Install packages
flutter analyze      # Must report "No issues found!" before opening a PR
flutter test         # Run all tests
flutter run          # Run the app on an emulator or a connected phone
```

After editing an `.arb` file, `flutter run` or `flutter pub get` regenerates `lib/l10n/app_localizations*.dart`. Commit the generated files together with the `.arb` changes.

## Code rules

- Keep the code simple and readable. Prefer clear, explicit code over clever one-liners.
- Manage state with `StatefulWidget` and `setState`.
- Use sqflite with plain SQL for the database. Do not use anything that needs code generation (`build_runner`).
- Do not add extra layers such as repositories, use cases or interfaces.
- Do not add new packages without asking first.
- Every screen lives in its own file in `lib/screens/`. When a file gets too long, split it into small widgets.
- Code and variable names are in English. Add short comments only where the code is hard to understand.
- Store money amounts as `int` in kuruş (e.g. 12.50 TL is `1250`). Never use `double` for money.
- IDs are `TEXT`: the Firebase Auth `uid` for users, a Firestore-generated ID for everything else.
- Every table except `sync_queue` has `updated_at INTEGER NOT NULL` and `deleted_at INTEGER` (milliseconds since epoch, `DateTime.now().millisecondsSinceEpoch`). Update `updated_at` on every change. Never `DELETE` a row; set `deleted_at` instead and filter with `WHERE deleted_at IS NULL`.
- Navigate between screens with `Navigator.push`.
- Every user-facing text goes into both `app_en.arb` and `app_tr.arb`; read it with `AppLocalizations.of(context)!`.

## Git workflow

- `main` is protected; all changes go through a pull request reviewed by at least one other team member.
- Branch names: `feature/receipt-scan`, `fix/balance-rounding`, `docs/readme`
- Commit messages start with a type: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`
- Every pull request adds an entry at the top of [docs/CHANGELOG.md](docs/CHANGELOG.md): date, title, author and a short list of what changed (see the format at the top of that file). This also applies to changes made with Claude Code.
- Never commit Firebase config files (`google-services.json`, `GoogleService-Info.plist`, `firebase_options.dart`); they are in `.gitignore`.
